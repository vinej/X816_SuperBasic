=== SYSTEM - the machine itself ===

[x] Ctrl-C - stop a running program. Checked between statements, which
    means a single statement that takes a long time cannot be broken
    into, and the check consumes the keystroke it reads.
[ ] Ctrl+Alt+PrtScr - this machine's RUN/STOP-RESTORE. The SMC raises a
    real NMI, so it works exactly where Ctrl-C cannot: a loop wedged
    inside one statement, or code that never reaches the break check.
    KIRQ_NMI (slot 8) is the hook and nothing installs it yet. This is
    the honest fix for Ctrl-C's blind spot rather than a duplicate of it.
[x] STOP / END - halt a program from inside it.
[x] CALL addr - call machine code. It runs in native mode; leave with RTL
    and preserve nothing but D and DBR if you also call the kernel.
[x] CLR - clear variables.
[x] NEW - erase the program.
[-] MONITOR - REMOVED. The machine-language monitor and the inline
    assembler are not built for SuperBasic. The keyword is still
    reserved and refuses, so nothing silently becomes a variable.

    They were inherited from BASIC816 and cost more than they were
    worth here: about 6.8 KB of the binary, and a fifth of the DIRECT
    PAGE - which is a single 256-byte page, was down to two free bytes,
    and is what every new feature needs a few of. Removing them took it
    back to 54. A BASIC for this machine does not need a 65816 monitor;
    the emulator has a debugger and X816_Calypsi has an assembler.

    The C256 build still has it, so that build still reproduces stock.
[x] QUIT - exit to the shell (K_EXIT). Until this there was no way out
    but resetting the machine, which is a poor answer on a computer
    whose whole boot story is "the shell runs an ordinary program".

    QUIT AND NOT ALSO SYSTEM. This page asked for both spellings and
    one is taken: a second name costs a token, and the token tables are
    the ceiling on finishing these pages while bytes are not - see
    PORT.md 29 for the counting.
[x] TURBO n - 0 for 8 MHz, anything else for 14 MHz. SYSCTL $9F80 bit 2,
    read-modify-write because bit 0 is the boot-ROM overlay and bit 1
    reads the CPU's live E flag. It is a clock ENABLE, not a clock
    switch, so it can be flipped at any moment: nothing glitches and no
    reset is needed.

    A number rather than the words on|off: a keyword is a token, and
    two of them for "yes" and "no" is two the rest of this page needs
    more.

    READING $9F80 BACK GIVES THE EFFECTIVE SPEED, which is this bit
    ORed with the MiSTer OSD's own Turbo setting. So TURBO 0 does not
    promise 8 MHz - it releases the software half of the decision. A
    program that needs to know should read the register rather than
    remember what it wrote.
[x] VER - the kernel version, (major << 8) | minor, from K_SYS_VERSION.
    Takes no parentheses, like TIMER and FRAMES.

    It is also the first keyword in the THIRD token table. The base
    table has been full since HELP LANGUAGE's two-byte scheme was
    built, and 43 of the items still on these pages want a keyword that
    does not exist yet against 37 sub-ids left - so $FF $FF <sub> now
    selects from a third table, and VER lives there to prove it. The
    same job VSYNC did for the second one.
[x] FRE - free memory, one number. HELP MEMORY.
[ ] REBOOT - restart the machine through the reset vector.
[ ] RESET - hardware reset via the SMC, the same one Ctrl+Alt+Del raises.
[ ] POWEROFF - power the machine off, also through the SMC.
[x] I2CPEEK(dev,reg) / I2CPOKE dev,reg,val - the I2C bus. The SMC is
    device $42, so I2CPEEK($42,$22) asks it for the mouse device ID.
    This is the back door to anything hanging off that bus, including
    parts of the keyboard and mouse that have no keyword of their own.
[x] IRQ slot,addr - install a MACHINE-CODE interrupt handler (K_IRQ_SET).
    Eleven slots, one per source, numbered:

        0 VSYNC     3 audio FIFO low   6 YM2151     9 BRK
        1 raster    4 VIA #1           7 spurious  10 COP
        2 collision 5 VIA #2           8 NMI

    Address 0 clears a slot. The handler is entered by JSL in native mode
    with 16-bit registers, D=0 and DBR=0, and must leave with RTL. It
    must NOT enable interrupts: the kernel's dispatcher has one scratch
    pointer and cannot be re-entered.

    Slots 1, 2 and 3 have their VERA enable bit set for you, after the
    install and never before - a source that asserts with no handler
    behind it is switched off by the kernel's stuck-source defence, so
    arming the hardware first works right up until it doesn't.

    Slot 0 is the one to think about: the kernel's blinking cursor lives
    there, and installing your own takes it away until something calls
    the cursor back. Its ENABLE is never touched by this statement -
    clearing it would stop FRAMES, WAIT and VSYNC dead.
[x] ONVSYNC target - run a BASIC subroutine once a frame. 0 disarms it.
[x] ONRASTER scanline,target - run one when the beam passes a scanline.
[x] ONCOLLISION target - run one when sprites collide.

    THE TARGET IS A LINE NUMBER OR A LABEL, and it is the same
    TARGET_FIND that GOTO, GOSUB and THEN use - so a name means the same
    thing everywhere in the language, and a label that works for one
    works for all of them:

        ONVSYNC tick
        ...
        LABEL tick
          N = N + 1
        RETIRQ

    A label is resolved when the handler is ARMED, to the number of the
    line it sits on, so the failure is reported by the statement that
    got it wrong rather than at whatever statement the frame landed on.

    NOT A PROC, and that is a decision rather than an omission. A
    deferred handler is entered as a GOSUB and left with RETIRQ; a
    DEFPROC is entered with a frame of locals and left with ENDPROC, and
    the two unwind different things. Aiming a handler at a DEFPROC would
    run the body and then pop a procedure frame nobody pushed. Making it
    work means deciding what ENDPROC does when the frame under it came
    from an interrupt, which is a language decision and not plumbing.
[x] RETIRQ - return from any of the three. Not RETURN: a handler can fire
    while your own GOSUBs are pending, and a RETURN reaching that frame
    would unwind to the wrong place silently. With this as the only way
    out, each mistake reports itself as a stack underflow.

    THE THREE ABOVE ARE DEFERRED, and it is worth knowing exactly what
    that means before building on them. The interrupt does not run your
    BASIC line. It sets nothing and calls nothing: the interpreter looks,
    BETWEEN STATEMENTS, at whether a frame went by - and if one did, it
    calls the handler then. So:

      - the handler runs at the next statement boundary, and a statement
        can be long. WAIT 5000, INPUT and a long PRINT all hold it off
      - a program slower than 60 statements a second DROPS ticks. They
        are never queued; queueing guarantees a spiral once the handler
        is slower than the source
      - a handler already running is never re-entered
      - RUN, NEW and LOAD all disarm every handler

    For a raster split - changing a register WHILE the beam is at that
    line - this is not good enough and never will be. Use IRQ 1,addr and
    write the handler in machine code. ONRASTER is for pacing to a point
    in the frame, not for splitting the screen.

    For exact frame timing, VSYNC (HELP TIME) is still the better tool:
    draw, VSYNC, draw is synchronous and never drops anything. ONVSYNC is
    for background work - a clock, a cursor, an animation counter - that
    can tolerate arriving late.

The machine boots to a shell; SuperBasic is an ordinary program the shell
runs, not the ROM. That is deliberate - it keeps BASIC replaceable and
leaves the machine useful for other languages. "run BASIC.BIN" at the
shell prompt is the whole of the boot story, and ESC after a program
exits reloads the shell.

Interrupts arrive MASKED from the shell and nothing else turns them on;
SuperBasic clears the flag in its entry sequence. A program that masks
them again loses the cursor, the frame counter and the audio refill all
at once.
