=== VIDEO - VRAM, screen modes and the font ===

These are the first statements written after the token table gained a
second half (PORT.md section 12); before that there were no keywords
left to give them.

VERA's 128 KB of video RAM is NOT in the CPU address space. It is reached
through a port: set an address in $9F20-$9F22, then read or write $9F23,
and the address auto-increments. Everything on the graphics pages - tiles,
sprite pixels, the palette, the font - lives behind that port.

[x] VPOKE addr,value - write a byte of VRAM. The address is 17 bits;
    bit 16 lives on its own in ADDR_H, whose upper nibble is the
    auto-increment and is left at zero here.
[x] VPEEK(addr) - read one back.
[x] VADDR addr - point the port once, then stream. Worth having as well
    as VPOKE: a bulk copy that re-sends the address for every byte does
    three writes where it needs one. Sets auto-increment; VPOKE leaves it
    clear, so a VPOKE between two VDATAs re-points the port and stops the
    stream rather than quietly walking on from somewhere unrelated.
[x] VDATA v [,v ...] - write bytes where VADDR left the port. THE LIST IS
    THE POINT: one VDATA of sixteen values is sixteen port writes and one
    statement, where sixteen VPOKEs are forty-eight port writes and
    sixteen statements - and in BASIC the statement is the expensive half.
[ ] SCREEN mode - 0 the text console, 128 the 320x240 bitmap. The X16's
    other text modes (80x30, 40x60, 40x30) are scale settings and could
    follow. HELP GRAPHIC for the VERA2 alternative at 640x480.

    POSTPONED ON PURPOSE, and not for want of the register writes. A mode
    is only usable if the kernel brings a font with it: the console's
    glyphs live in VRAM at a place the current mode put them, and a
    statement that changed the mode without moving the font would leave a
    machine that cannot print the error message telling you so. It waits
    on the kernel supporting every mode with its font, and then it is
    small.
[x] BORDER c - the border colour.
[x] CURSORX / CURSORY - read the cursor position back. Written since
    phase 5 and unreachable until the tokenizer learned to tell a
    no-argument function from a negation; see tokens.s, TKPREVFN.
[x] SCROLLX n / SCROLLY n - HARDWARE scroll of the console layer,
    0-4095. Free smooth scrolling with no redraw at all, which is the
    difference between a playable game and a slideshow on a machine this
    size. Only the low nibble of each high byte is the scroll, so both
    are read-modify-write; clobbering the rest disturbs the layer.

--- the font ---

The console is VERA layer 0 and its font is ordinary VRAM the kernel
filled at boot. There is NO character ROM, so unlike the C64 or the X16
there is no ROM number to select - a font is an address, and anything you
can write is a font. This is the redefinable-character-set feature, and
for a beginner's BASIC it is one of the most rewarding things on any of
these pages: it is how you get a game's tiles and a custom alphabet
without touching sprites or bitmaps.

A font is 256 glyphs of 8 bytes = 2 KB, on a 2 KB boundary. A glyph is 8
bytes, one per scanline, top first, bit 7 leftmost. Codes are CP437 and
the tile index IS the character code - no $20 bias, so 65 really is "A".
The kernel's font sits at VRAM $4000, with the tilemap below it at
$00000-$03FFF; $4800 is the next free slot.

[x] CHARSET addr - point the console at a font. The address is stored
    shifted right eleven, so it must be on a 2 KB boundary; anything
    finer would be silently rounded down by the hardware, which is a
    baffling way to find out, so it is refused instead.
[x] CHARSETAT - where the console is reading its font from now. Takes no
    parentheses, which needed the tokenizer fix in tokens.s (TKPREVFN).
    This is what makes CHARSET safe from a program: save it, point
    somewhere else, put it back.
[x] GLYPH addr,n,d0,d1,d2,d3,d4,d5,d6,d7 - redefine character n. Eight
    bytes is awkward as arguments, and READing them from DATA in a loop
    is the friendlier form; but this spelling needs nothing else to
    exist, so it is the one that got written.
[x] GLYPHGET(addr,n,row) - read one scanline of a glyph back. A
    FUNCTION OF THREE ARGUMENTS, where this page used to ask for a
    statement taking an array, because eight bytes need somewhere to go
    and an array is somewhere. An array also needs integer-array plumbing
    that nothing here has yet - the one array argument in the language,
    SPLIT's, takes a STRING array and only that - where a function that
    answers one row needs none:

        FOR R = 0 TO 7 : D(R) = GLYPHGET($4000, 65, R) : NEXT

    and it reads back into anything rather than only into an array: PRINT
    it, compare it, edit one scanline without a nine-argument statement.
[x] FONTCOPY src,dst - duplicate 2 KB of font. VERA has TWO address
    pointers with a data port each, and DATA0 always steps pointer 0
    while DATA1 always steps pointer 1 - so this needs no buffer in main
    memory and the inner loop is a load and a store.

Copy before you edit. Editing the font at $4000 edits the one being drawn
with, including the message telling you what went wrong, and there is no
way back short of a reboot. Copy it to $4800, edit that, then point
CHARSET at it - and CHARSET $4000 typed blind still puts it back.
