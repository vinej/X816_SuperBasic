=== MATH - arithmetic, and why it is software ===

On the C256 that BASIC816 came from, this page was hardware: floats went
through a memory-mapped FP coprocessor and integer multiply drove a
multiplier in the GABE chip. Neither exists on the X816, so all of it is
software here - X816/floats_x816.s and X816/ints_x816.s. That rewrite is
the largest single piece of the port.

[x] + - * / and unary minus, on 32-bit integers and floats.
[x] ^ - raise to a power. A whole-number exponent is repeated
    multiplication; a fractional or negative one goes through
    EXP(y * LN(x)), so 2^0.5 is 1.41421 and 2^-1 is 0.5.
[x] MOD - remainder, from the software divide. Unsigned: it takes the
    magnitudes, so a negative operand does not give the answer you want.
[x] = <> < > <= >= - comparison, integer, float and string.
[x] AND OR NOT - bitwise and logical.
[x] ABS SGN INT - sign and truncation.
[x] RND(x) - a random float in [0,1). No RNG hardware, so this is a
    16-bit xorshift seeded at startup. The argument is evaluated and
    ignored, as it was on the C256.
[x] VAL STR$ HEX$ DEC PARSEINT - conversion between text and number.
[x] SIN COS TAN - real. Five Horner terms on [-pi/4, pi/4]; the whole
    circle folds into that range by subtracting multiples of pi/2 and
    remembering how many. Worst error against double precision is under
    1e-7, well inside the six digits PRINT shows. TAN is sin/cos, so
    TAN(pi/2) reports division by zero rather than an infinity.
[x] ASIN ACOS ATAN - real. ATAN folds any magnitude under tan(pi/8)
    with the tangent addition formula and then runs four terms; ASIN is
    atan(x/sqrt(1-x*x)) and ACOS is pi/2 minus it, so neither needs a
    polynomial of its own. Outside [-1,1] ASIN and ACOS are a domain
    error.
[x] LN EXP - real. A float already carries the integer part of its own
    logarithm in the exponent field, so LN only computes ln(m) for the
    mantissa and adds e*ln2; EXP is the same trick backwards, and builds
    its power of two by writing an exponent field rather than
    multiplying. EXP overflows to an error and underflows to zero.
[x] SQR - square root. Newton-Raphson over the software float ops,
    seeded by halving the exponent field, four iterations. A negative
    operand is a domain error rather than a NaN.

Nothing on this page throws any more, and none of it is a port. The
C256 versions are not built on the arithmetic primitives at all - they
contain about ninety direct accesses to the FP coprocessor's registers,
and on this machine those addresses are plain SDRAM, so running that
code would have read whatever happened to be there and returned a
confident wrong answer. All of it is written fresh against the software
float engine.

Every coefficient set was checked against double precision before being
written down; the worst case each way is under 2e-7, which is inside the
six digits PRINT shows. The reductions are the part worth distrusting
rather than the polynomials, so the tests pick arguments that exercise
them: COS(10) is past three quadrants, ATAN(10) is past both folds.

Floats are IEEE-754 single precision: sign, eight exponent bits, 23
mantissa bits. The engine truncates rather than rounds, and denormals
flush to zero, so results can sit an ulp or two below a correctly
rounded answer - PORT.md section 11 records one measured case.

Printing does not match the format most people expect. PRINT gives six
significant digits and adds an exponent whenever the decimal exponent is
not zero, so 1024 prints as 1.02400E03. That is upstream BASIC816
behaviour, identical on the C256, and not a fault in the port - but it
is the sort of thing SuperBasic should probably change.

Operators of equal precedence evaluate LEFT TO RIGHT: 10-5+2 is 7,
100/10/2 is 5, 2^3^2 is 64. That sentence is on this page because it
was NOT true until 2026-08-09: the evaluator resolved ties to the
right, so 10-5+2 answered 3 and 100/10/2 answered 20, on every build
since BASIC816 and on the C256 today. Any older program that leaned on
the broken order - if one exists - will now get arithmetic instead.

Two edges of that rule are worth knowing. -2^2 is -4, because ^ binds
tighter than the minus sign in front of a number - the same answer
Microsoft BASIC gives, and the same reason SQR(2)^2 needs no
parentheses. And prefix operators still chain from the right: 10--5 is
15, NOT NOT A is A.
