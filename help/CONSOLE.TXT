=== CONSOLE - text screen and colour ===

The console is 80x60, CP437/ASCII (no PETSCII), and belongs to the
kernel: SuperBasic reaches it through the jump table at $00:FE00 rather
than by poking VERA. See X816_core/doc/KERNEL.md section 4.

[x] PRINT expr[,expr][;] - print. A trailing ";" suppresses the newline,
    "," tabs to the next field.
[x] CLS - clear the screen and home the cursor (K_CON_CLS).
[x] LOCATE col,row - move the cursor. Columns 0-79, rows 0-59.
[x] TEXTCOLOR fg,bg - set the colour of everything printed from now on.
    Both 0-15. Text already on screen keeps the colour it was drawn with.
[x] TAB(n) / SPC(n) - column and spacing control inside PRINT.
[x] SETCOLOR index,rgb - reprogram one of the 16 text colours. It is the
    same store PAL makes with the index held to 0-15, which is the point
    of it: 0-15 ARE the text palette, so 200 is a mistake here. HELP PAL.
[x] SETBGCOLOR c - the background of everything printed from now on,
    0-15. TEXTCOLOR's second argument on its own, with the foreground
    left exactly where it was.

    That last part is the whole of the work. The kernel takes the pair
    together and has no call to ask what they currently are, so setting
    half of a pair means REMEMBERING the other half: TEXTCOLOR keeps a
    shadow, and it is seeded at startup with what the kernel's console
    actually boots at (foreground 1 on background 0) rather than with a
    guess. A shadow made of powered-up RAM would have set the
    foreground to noise the first time anybody changed only the
    background.

    Text already on screen keeps the background it was drawn with. The
    attribute is a pen, not a property of the screen - the same rule
    TEXTCOLOR has.
[x] SETBORDER c - the colour around the display, 0-255. It is a PALETTE
    INDEX, not an RGB triple: the C256's SETBORDER took a visibility
    flag and three colour components, and VERA's border is one byte
    indexing the same 256 colours PAL writes.

    It is the same statement as BORDER (HELP VIDEO) under a second
    name, and that is worth saying rather than hiding. HELP AUDIOPCM
    removed PCMPUT for being one page asking twice for one thing; this
    is two pages asking once each, and SETBORDER's token was spent by
    BASIC816 long before this port. Keeping it costs nothing today, and
    the slot can be reclaimed if the base token table ever needs one -
    SAVE writes ASCII, not tokens, so no stored program would notice.
[ ] SCREEN mode - pick a text or bitmap mode. HELP GRAPHIC.
[x] CHARSET addr - point the console at a different font in VRAM. There
    is no character ROM here, so this takes an address, not a ROM
    number. Built with the rest of the font work - HELP VIDEO has it and
    CHARSETAT, which is what makes it safe to use from a program.

Two console behaviours are worth knowing because they are not the C64's:

The cursor is a VSYNC interrupt handler in the kernel, armed only around
a key wait. It is why interrupts must be enabled - see PORT.md section 4.

$0D is carriage-return ONLY on this console: column 0 of the SAME row.
$0A is what advances a line. SuperBasic's putc translates CR to LF so
PRINT behaves; a program poking the console directly must do the same.

Reading the screen back: there is no kernel call for "character at x,y",
so the REPL reads the VERA text matrix directly (screen_x816.s,
SCRCOPYLINE). Glyphs are CP437, one byte, so the byte read IS the
character; attributes are interleaved and skipped.
